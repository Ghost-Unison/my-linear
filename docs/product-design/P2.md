## 1. 总决策

1. **实施顺序**（frontend-driven）：Filter 面板（后端过滤契约 + 面板 UI）→ Display options 面板（纯前端）→ 视图持久化（saved_view CRUD + 页面 tab）→ Views 页 → 验证回写。面板是本体，视图只是面板状态的持久化壳。
2. **状态存放（方案 A，2026-09 拍板）**：filter 状态进 URL（延续现有 `?filter=` tab 的同步能力并扩展为面板条件编码）；display options 纯前端内存、刷新重置、可被 view 固化；项目列表表头排序**前端化**，退掉 `GET /projects` 的 `sort`/`order` 后端参数，ordering 单一路径（表头点击与面板 Ordering 共享同一前端状态）。任务列表 SQL 固定 ORDER BY 保留为"无 ordering 时的基底序"，前端排序覆盖其上。
3. **行完备原则延续**（api.md §2.9）：display 控制（分组/排序/展示属性/子任务开关）是前端对已取回平铺行集的内存操作，切换不发请求；**仅 filters 翻译成列表接口查询参数发请求**。响应形状零变更。
4. **tab 与面板状态统一（A2 实施修订，取代原"tab = status 条件 UI 糖"方案）**：Active/Backlog/All tab 是前端**隐式基底作用域**——独立 URL 参数 `?tab=`（不显示为 chip、不进 f=），请求时合成 `f= = tab 基底条件 + chip 条件`（AND 叠加；Active = `status.isAnyOf.todo,in_progress`、Backlog = `status.is.backlog`、All = 不附加）。切 tab 只改写 tab 键保留 f=；面板 status 条件与 tab 互不覆写。后端 `filter=` 遗留别名随之退役（删除 `legacyStatusConds` 与 handler 分支）。原案"点 tab = 覆写 status 条件、tab 按条件是否恰等于预设决定高亮"废弃：覆写会破坏用户手加的 status chip，高亮判定复杂且 Linear 实测 tab 与 chip 层独立。
5. **saved_view 双轨隔离**：加 `surface` 列（`tasks_page` / `projects_page` / `views_page`）。页面级 view 只出现在对应列表页 tab 行；Views 页只列 `views_page` 的 view（对齐 Linear 实测行为：两处互不可见）。
6. **操作符语义（定稿 v2，2026-09 Linear 实测真值表）**：操作符集合随选中值个数联动（UI 层控制菜单展示与文案，wire 承载全量操作符）：

   | 字段类型 | 选中值个数 | 操作符（wire） | 集合语义 |
   |----------|----------|--------|----------|
   | 单值字段（status / priority / assignee / lead / project） | 1 值 | `is` / `isNot` | 值 = / ≠ 所选值 |
   | | ≥2 值 | `isAnyOf` / `isNot` | 值 ∈ 集合（OR）/ ∉ 集合（NULL/空伪值行按伪值参与判定，见 §2.3） |
   | 多值 labels 族（labels） | 1 值 | `inclAll` / `exclAny` | include / do not include |
   | | ≥2 值 | `inclAll` / `inclAny` / `exclAny` / `exclAll` | 所选 ⊆ 行集合 / ∩ ≠ ∅ / ∩ = ∅ / ⊄ 行集合 |
   | 多值 members 族（member） | 任意 | `inclAny` / `exclAny` | contains any / does not contain（文案随值个数切 contains / contains any） |
   | 日期字段 | 单值 | `before` / `after`（`is`/`isNot` 承载 none 空值条件） | 相对阶梯 cutoff 比较（§2.4） |

7. **组合语义**：条件为**有序列表**（同字段可重复出现多条 chip，图13 两个 Status），整表 AND；面板条件与 URL 中其他条件同层 AND。
8. **三层状态模型（filter/display/view 通用，2026-09 Linear 实测定稿）**：currentState（页面活状态 = filters 条件列表 + display，filters 镜像进 URL）是唯一真相源；view 是服务端某时刻 currentState 的快照（config 深拷贝）；编辑态再叠一层 draft。**任何修改只动顶层状态，永不自动写回 view.config**——写回只发生在三个显式动作：保存新视图 / Save to this view / 编辑态 Save。
9. **view 激活下的两条修改路径**：不进编辑态 = 直接改 currentState、列表实时响应、tab 显示偏离点、chip 行 Save 升级为分裂下拉（Save to this view = PATCH config ← currentState；Create new view... = 另存弹窗并切换激活）；编辑态（tab 右键 Edit 进入）= 视图信息卡（name/description 行内可改 + Cancel/Save）+ chip 行与 display 面板操作 draft 并实时预演，Save 元数据+config 一起提交并退出，Cancel 草稿全弃回到进入前状态。带偏离切 tab/导航 = 丢弃偏离（filters 部分随 URL 走）。
10. **展示优化批后置 P3（2026-09 用户拍板）**：Sub-grouping 二级分组、Show empty groups、组序方向切换、hidden-by-filters 隐藏计数空态、视图图标选择器（P2 tab 用固定层叠图标）；同批裁剪项：逐值命中计数、AI filter / Advanced filter、菜单搜索框、Board/Timeline 布局段、Show closed projects、Duplicate/Favorite/Copy link、Custom date 档。

## 2. Filter 面板

### 2.1 入口与形态（Linear 实测定稿）

- 页头右侧 filter 按钮（圆形漏斗图标，页头三按钮统一圆形形态）→ **纯添加**级联菜单（shadcn DropdownMenu 实现，二级面板经 Radix Sub **悬浮飞出**）：一级字段清单 → 二级值多选勾选清单（单值/多值字段）或日期字段清单（Dates）→ 三级相对阶梯；菜单**不显示已有条件**（同字段再加一条 = 新条件 chip，§1.7）。
- 添加后的条件落在 **chip 行**（tab 行与表头之间）：chip 三段可点——字段（静态）/ 操作符（点开该字段随值个数联动的操作符清单切换）/ 值（重开多选；日期字段为阶梯单选清单）——加 × 删除；行尾 `+` 添加、`Clear` 全清、`Save` 进视图保存流程（§4）。
- 添加时默认操作符：单值 = is、labels 族 = inclAll、members 族 = inclAny、日期随阶梯方向（ago = after / from now = before，§2.4）。操作符文案随选中值个数切换（is → is any of、include → include all of 等）；值个数变化时操作符等价归一（isAnyOf 单值 → is 等）。
- 多值字段 none 哨兵与真实值**互斥**（勾 No labels 即取消其它勾选）；单值字段可混选（No lead + 真人 = 未指派 OR）。
- 值行**分两区**（Linear 界面实测定稿）：checkbox 勾选区点击 = 本会话累积勾选（多选自动**合并为一个 chip**，菜单**不关闭**，可继续勾该属性其它选项或切其它属性）；其余区（文字）点击 = 单值直接成**一条 chip** 并**关闭整个菜单**（不再有机会点第二个选项）。
- 多选子面板贴近视口右缘时 Radix 会把飞出清单 popper 翻到 side=left，触发 onItemLeave 抢焦点误关 Sub——用**悬挂守卫**（指针仍在飞出清单内时忽略 focus-outside）阻断误关，指针移开其它字段行仍照常互斥关闭。
- filter / display / panel 收缩三按钮统一圆形形态；filter / display 按钮在非默认状态时亮蓝点。

**Projects 页**：

**项目详情 Issues tab**（第三个列表面，`GET /projects/:projectId/tasks`）：共享 Tasks 页字段矩阵与后端白名单（同 `f=` 契约）；project 字段在本面隐含（行必属当前项目），前端 Filter 菜单不提供。本面视图归属切片 C 定（§4.1 注）。

### 2.3 空伪值契约

可空单值字段（assignee / lead / project）与多值 labels 族字段（labels）的值选择器提供空伪值选项（No assignee 等），wire 上编码为哨兵值 `none`；日期字段 startDate 亦提供 No start date：

- 单值可空：`none` ↔ NULL 双向映射；`isNot [x...]` 时 NULL 行按"伪值 ∉ 集合"判定 → **包含 NULL 行**（"assignee 不是 Lee"包含未指派任务，与 Linear 直觉一致）。单值字段 none 与真实值可混选。
- 多值：`none` 选中 = 空集合行；`inclAll [none]` = 无标签/无成员的行；`exclAny [none]` = 至少有一个标签/成员的行。**none 与真实值互斥**（勾 No labels 即取消其它勾选，Linear 实测）。
- members 字段不提供 none 选项（Linear 实测真值表）。
- priority 的 No priority 是真实值 0，不走哨兵。
- 日期空值条件走 `is`/`isNot` + `none`（No start date / No due date）；before/after 不参与空值判定。

### 2.4 日期相对条件

条件 = {字段, before|after, 阶梯码}（空值条件 = {字段, is|isNot, none}；逾期谓词 = {dueDate, is|isNot, overdue}，阶梯清单置顶行，chip 读作 "Due date is Overdue"；is = 非空且早于今天，今天到期不算逾期）。阶梯**按字段分方向**（Linear 实测真值表）：createdAt / updatedAt = ago 七档 `1d / 3d / 1w / 1mo / 3mo / 6mo / 1y`；startDate = from now 七档（同码未来偏移）+ No start date；targetDate = from now 仅三档 `3mo / 6mo / 1y`；dueDate = from now 仅五档 `1d / 3d / 1w / 1mo / 3mo`（Linear 实测无 6mo/1y）+ No due date + Overdue（Custom date or timeframe 后置 P3）。cutoff 由 **Go 层计算**（可测试）：timestamptz 列（createdAt/updatedAt）cutoff = now()±offset 比时刻；date 列（dueDate/startDate/targetDate）cutoff = today±offset 比日历日（civil.Date 算术；ago 取 −、from now 取 +）。`before` = 早于 cutoff、`after` = 晚于 cutoff。添加默认操作符：ago 档 = after（"晚于 N 前" = 近 N 内）、from now 档 = before（"早于 N 后" = 未来 N 内），chip 可切。

### 2.5 URL 编码与后端求值契约

- URL：重复查询参数 `f=<field>.<op>.<v1,v2>`，如 `f=status.isAnyOf.todo,in_progress&f=labels.inclAll.l1,l2&f=dueDate.after.3d&f=assignee.is.none&f=startDate.is.none`；解码白名单校验，非法条目静默丢弃（回退无该条件）。
- **求值层：Go 层条件列表引擎（internal/filter 包），2026-09 修订原"下沉 sqlc 数组参数"方案**。修订理由：条件列表模型条数动态（同字段可重复），sqlc 固定形状查询无法承载；多值字段重复 include 条件的 AND 无法折叠为单个数组参数（incl A ∧ incl B ≠ incl A∪B）；不分页前提下全量行集本就取回内存，labels/members 联结数据可在求值前批量取齐，与既有"动态排序放 Go 层"约定（api.md §2.2）同构，NULL/伪值语义单点可测试。
- 引擎契约：`filter.Parse`（f= 数组 + 实体字段白名单 Spec，非法条目静默丢弃）→ `filter.Apply`（行集 + 条件列表 + 实体字段值提取器，条件间 AND）。SQL 只保留基础谓词（workspace + 软删）与基底序；`ListTasksByWorkspace` 的 statuses 数组参数退役（handler 恒传非 nil 空切片，随后续查询清理删除）。
- 求值联结数据：labels 走既有 `ListLabelsByTaskIds` / `ListLabelsByProjectIds`；项目 member 集合走新增 `ListProjectMemberIdsByProjectIds`（仅 member 条件存在时批量取）。
- 遗留参数：`filter=`（tasks）**已退役**（2026-09 A2 前端 tab 迁移完成，后端删除 `legacyStatusConds` 与 handler 分支；tab 作用域由页面侧合成进 f=，§1.4）；`sort=`/`order=`（projects）保留至 display options 切片前端化 ordering 时退役。
- React Query 键含 `f` 参数 → 过滤切换发请求；display 切换不进键、不发请求。

### 2.6 树形视图与过滤的交互

子任务命中而父未命中：子提升顶层渲染，flat 模式带父面包屑（延续 P0 行为）；父命中而子未命中：子不渲染（Show subtasks 关时同理，只渲染顶层任务）。

## 3. Display options 面板

页头右侧第二按钮（Linear 同款滑杆图标）→ popover 四 section。**全部纯前端内存操作，不发请求、不进 URL**。

### 3.1 Grouping

- Tasks：none / status / priority / assignee / project / **label**；Projects：none / status / priority / lead / **label**。
- **label 分组 = 重复入组语义**（对齐 Linear）：行在每个所属标签组各出现一次；组序 = 标签创建序；No labels 组恒最后。组头计数含跨组重复。
- 其余字段空值行归 "No X" 组（恒最后）；组序：枚举按生命周期/priority 业务序，实体（assignee/lead/project）按 created_at。
- **Nesting × 分组规则**：Nesting 开时为组内嵌套——子仅在父同属该组时挂父下，否则在该组作顶层行（flat 模式带面包屑）。
- Sub-grouping（二级分组）后置 P3（§1.10），P2 仅单级分组。
- 分组折叠不做（与现状一致）。

### 3.2 Ordering

单字段 + 方向。Tasks：createdAt / updatedAt / priority / status / dueDate / title；Projects：name / createdAt / updatedAt / priority / status / targetDate。稳定排序（同值保持基底序）。Projects 页表头点击 = 写此状态（前端内存），表头箭头反映面板状态；Tasks 页无表头，ordering 仅面板入口。默认序 = 现状基底序（tasks：status 业务序 + created_at；projects：created_at desc）。

### 3.3 Display properties

行内 chip/列开关，默认全开 = 现状渲染：

- Tasks 行：priority / status / assignee / dueDate / labels / project；
- Projects 行：status / priority / lead / dates / taskCount / labels（**P1 行完备预留项在此落地**）。

行布局遵循既有 Task list row layout 规范；开关只控制渲染与否，不改行网格契约之外的几何。

### 3.4 Subtasks（仅 Tasks 页）

Show subtasks 开关 + Nesting 开关，**替换 P0 的 tab 驱动 tree/flat 硬编码**（[TaskListPage](../../myLinearFrontEnd/src/pages/tasks/TaskListPage.tsx) 的 `view={tab === "all" ? "tree" : "flat"}` 退役）：Show off = 只顶层；Show on + Nesting on = 树形；Show on + Nesting off = 平铺带面包屑。与 tab 解耦后，Active/Backlog 下也可开树形。

## 4. 视图持久化（saved_view）

### 4.1 数据与迁移（v1.4）

`CREATE TYPE view_surface AS ENUM ('tasks_page','projects_page','views_page')`；`saved_view` 加 `surface view_surface NOT NULL DEFAULT 'views_page'`；索引 `(workspace_id, entity_type)` 改为 `(workspace_id, surface, entity_type)`。surface 与 entity_type 一致性由后端强制：`tasks_page ⇒ task`、`projects_page ⇒ project`；`views_page` 两者皆可（Views 页 tab 区分）。

> **项目详情 Issues tab 的视图归属（切片 C 定，此处登记）**：Linear 中该面有独立 view 切换器（Issues tab 旁层叠图标），视图按项目隔离。候选方案：surface 枚举加第四值（如 `project_issues`）+ `saved_view` 加可空 `project_id` 列做项目级 scope。切片 A 已先行接通本面 `f=` 过滤契约（§2.2）。

### 4.2 config JSON 契约（后端 opaque，前端读写）

```json
{
  "filters": [{ "field": "status", "op": "isAnyOf", "values": ["todo", "in_progress"] }],
  "display": {
    "groupBy": "priority",
    "ordering": { "field": "createdAt", "dir": "desc" },
    "visible": { "priority": true, "status": true, "assignee": true, "dueDate": true, "labels": true, "project": true },
    "showSubtasks": true,
    "nesting": true
  }
}
```

filters 条目与 URL `f=` 编码同构（field/op/values 三元组，values 含 `none` 哨兵与阶梯码）；display 键即面板四 section 状态。后端不解释、不校验内容（仅要求 JSON object）。

### 4.3 接口（api.md §10）

| 接口 | 说明 |
|------|------|
| GET /workspaces/:wid/views?surface=&entityType= | 列表；surface 必传，entityType 仅 views_page 需要 |
| POST /workspaces/:wid/views | {name, description, surface, entityType, config}；name trim 非空；**不做重名约束** |
| GET /workspaces/:wid/views/:viewId | 单条（视图详情页用） |
| PATCH /workspaces/:wid/views/:viewId | name / description / config（presence 三态） |
| DELETE /workspaces/:wid/views/:viewId | 硬删除 |

### 4.4 页面级 view（列表页 tab 行）

- tab 行 = 预设 tab（§1.4）+ 该页 surface 的 view tab（固定层叠图标 + name，图标选择器后置 P3）+ "+" 按钮（SaveViewDialog：name + description，捕获当前 filter+display 全状态，surface=当前页）；保存成功后新 view **自动激活**。
- 点 view tab：URL 写 `view=<id>` + config.filters 物化为 `f=` 参数；config.display 载入内存。
- **view 激活下的修改走 §1.9 两条路径**：不进编辑态时 Save 分裂下拉（Save to this view / Create new view...）；编辑态（tab 右键 Edit）展开视图信息卡（name / description 行内可改 + Cancel/Save），chip 行与 display 面板操作 draft 并实时预演，Save 元数据+config 一起提交并退出，Cancel 全弃。
- tab 右键菜单：Edit / Delete（确认弹窗）两项（Duplicate/Favorite/Copy link 裁剪，§1.10）。
- 偏离点：当前状态 ≠ view.config 时 tab 显示偏离点（写回后消失）。

### 4.5 Views 页（workspace 级）

- 新路由 `/w/:wid/views` + 侧栏 Workspace 组 Views 入口；页头 Issues / Projects 双 tab（entity_type）+ New view 按钮。
- 行：视图图标 + name + description（对齐 Linear 行形态；**owner 列裁剪**，无登录体系）。
- New view：创建空 config view（surface=views_page、entityType=当前 tab）并跳转详情页。
- 详情页 `/w/:wid/views/:viewId`：按 config 渲染列表（复用 TaskGroupList / 项目列表组件与面板组件，状态由 config 初始化），页内可继续改 filter/display 并 Update view；页头显示 view name（可 rename）。
- 隔离查询：列表页 tab 只查 surface=当前页；Views 页只查 surface=views_page —— 双轨互不可见。
