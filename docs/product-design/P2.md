## 1. 总决策

1. **实施顺序**（frontend-driven）：Filter 面板（后端过滤契约 + 面板 UI）→ Display options 面板（纯前端）→ 视图持久化（saved_view CRUD + 页面 tab）→ Views 页 → 验证回写。面板是本体，视图只是面板状态的持久化壳。
2. **状态存放（当前实现）**：浏览 URL 的 `f=` 承载临时 filters；`projects_page` / `tasks_page` 的 `view=` 指向保存基底，**不把 config.filters 物化进浏览 URL**。请求 `GET /projects` / `GET /tasks` 时前端将保存 filters 与临时 filters 合成 `f=`，后端按 AND 求值。display 纯前端内存，可显式保存到 config；两列表页刷新后从保存 config.display / 预设默认初始化，临时 filters 从 URL `f=` 恢复，未保存 display 不保留。项目列表表头排序已**前端化**，`sort`/`order` 后端参数退役，表头与面板 Ordering 共享状态。任务列表 SQL 固定 ORDER BY 保留为 Manual 基底序，前端排序覆盖其上。
3. **行完备原则延续**（api.md §2.9）：display 控制（分组/排序/展示属性/子任务开关）是前端对已取回平铺行集的内存操作，切换不发请求；**仅 filters 翻译成列表接口查询参数参与取数**（命中缓存可复用）。display 切换不改变响应形状；B 切片已按行完备原则补入 ProjectRow.members。
4. **tab 与面板状态统一（A2 作用域方案，2026-09-22 Tasks View 接入修订）**：Active/Backlog/All tab 是前端**隐式基底作用域**——独立 URL 参数 `?tab=`（基底条件不显示为 chip、不写入浏览 `f=`），请求时合成 `f= = tab 基底条件 + 临时 chip 条件`（AND 叠加；Active = `status.isAnyOf.todo,in_progress`、Backlog = `status.is.backlog`、All = 不附加）。**每个预设 tab 独立缓存临时 filters/display，切 tab 恢复目标缓存，无缓存时为空 filters + 默认 display**，不再将同一组 `f=` 带到所有 tab；面板 status 条件与预设基底互不覆写。自定义 View 以 `view=` 为基底，不叠加来源预设 status；新建/编辑预览仅用 draft。后端 `filter=` 遗留别名已退役（删除 `legacyStatusConds` 与 handler 分支）。原案“点 tab 覆写 status 条件、按条件是否恰等于预设决定高亮”仍废弃：预设作用域与临时 chip 分层。
5. **saved_view 双轨隔离**：加 `surface` 列（`tasks_page` / `projects_page` / `views_page` / `project_issues`）。页面级 view 只出现在对应列表页 tab 行；Views 页只列 `views_page` 的 view（对齐 Linear 实测行为：两处互不可见）；`project_issues` 面 view 带 `project_id` 做项目级隔离（§4.1）。
6. **操作符语义（定稿 v2，2026-09 Linear 实测真值表）**：操作符集合随选中值个数联动（UI 层控制菜单展示与文案，wire 承载全量操作符）：

   | 字段类型 | 选中值个数 | 操作符（wire） | 集合语义 |
   |----------|----------|--------|----------|
   | 单值字段（status / priority / assignee / lead / project） | 1 值 | `is` / `isNot` | 值 = / ≠ 所选值 |
   | | ≥2 值 | `isAnyOf` / `isNot` | 值 ∈ 集合（OR）/ ∉ 集合（NULL/空伪值行按伪值参与判定，见 §2.3） |
   | 多值 labels 族（labels） | 1 值 | `inclAll` / `exclAny` | include / do not include |
   | | ≥2 值 | `inclAll` / `inclAny` / `exclAny` / `exclAll` | 所选 ⊆ 行集合 / ∩ ≠ ∅ / ∩ = ∅ / ⊄ 行集合 |
   | 多值 members 族（member） | 任意 | `inclAny` / `exclAny` | contains any / does not contain（文案随值个数切 contains / contains any） |
   | 日期字段 | 单值 | `before` / `after`（`is`/`isNot` 承载 none 空值条件） | 相对阶梯 cutoff 比较（§2.4） |

7. **组合语义**：条件为**有序列表**（同字段可重复出现多条 chip，图13 两个 Status），整表 AND；面板条件与 URL 中其他条件同层 AND。
8. **三层状态模型（当前落地 projects_page / tasks_page）**：view.config 是保存基底；浏览态 = 保存 filters AND 当前 tab 的临时 filters + 当前 display；draft 是独立编辑沙箱。每个 tab 的临时 filters/display 与每个已有 View 的编辑草稿（名称、描述、filters、display）**仅在本次页面会话内分别缓存，互不覆盖**。切 tab 关闭编辑 panel：已有 View 草稿暂存，新建草稿丢弃；点击 tab 仅恢复浏览态，再次 Edit 才恢复暂存草稿。离开页面卸载（含切 workspace）缓存丢失，刷新按 §1.2 初始化。**浏览与编辑均不自动写回 view.config**——写回只发生在保存新视图 / Save to this view / 编辑态 Save。project_issues 与 workspace Views 页的视图生命周期尚未接入。
9. **view 浏览与编辑（projects_page 于2026-09-21定案，tasks_page 于2026-09-22同规则接入）**：点击 tab 仅浏览，保存 filters 仅在 hover/详情只读展示；浏览修改只动临时层。新建/编辑为行内 panel，预览仅用草稿，顶部 Filter/Display 隐藏、仅 panel 内两入口互斥；New project / New task 和 tab 行 "+" 保留。普通 "+" 新建 = 空名称/描述/filters + 点击前生效的 Display（含当前编辑改动）；临时条 Create new view = 全部生效 filters/display；已有 View 的 Edit 优先恢复暂存草稿，无草稿时才深拷贝保存配置。**新建全程无 Display 蓝点和 Reset；已有 View 的 Reset = 还原保存值，Cancel = 丢弃编辑草稿并回到原浏览状态，切 tab = 暂存已有 View 草稿**。零 filters 和仅 Display 修改均可保存（名称 trim 非空）。完整状态转换、保存交接、指示与 Reset 规则以 **§4.4.1** 为准；不得再使用“切 tab 一律丢 draft”或“新建对比全局默认亮点”的旧规则。
10. **展示优化批后置 P3（提前项见 §3 as-built 注）**：Sub-grouping / Show empty groups 已在 projects_page、tasks_page、project_issues 三面落地，Show closed projects 已在项目面落地；仍后置组序方向切换、hidden-by-filters 隐藏计数、视图图标选择器（P2 tab 用固定层叠图标）。其余裁剪/后置项：逐值命中计数、AI filter / Advanced filter、菜单搜索框、Board/Timeline 布局段、Duplicate/Favorite/Copy link、Custom date 档。

## 2. Filter 面板

### 2.1 入口与形态（Linear 实测定稿）

- 页头右侧 filter 按钮（圆形漏斗图标，页头三按钮统一圆形形态）→ **纯添加**级联菜单（shadcn DropdownMenu 实现，二级面板经 Radix Sub **悬浮飞出**）：一级字段清单 → 二级值多选勾选清单（单值/多值字段）或日期字段清单（Dates）→ 三级相对阶梯；菜单**不显示已有条件**（同字段再加一条 = 新条件 chip，§1.7）。
- 添加后的条件落在 **chip 行**（tab 行与表头之间）：chip 三段可点——字段（静态）/ 操作符（点开该字段随值个数联动的操作符清单切换）/ 值（重开多选；日期字段为阶梯单选清单）——加 × 删除；行尾 `+` 添加、`Clear` 清当前可编辑条件。projects_page / tasks_page 的浏览 chip 仅含临时 filters，另有 `Reset`/`Save`（§1.9），仅 Display 改动也出现临时条并可保存；project_issues 的 `Save` 仍为禁用预留。
- 添加时默认操作符：单值 = is、labels 族 = inclAll、members 族 = inclAny、日期随阶梯方向（ago = after / from now = before，§2.4）。操作符文案随选中值个数切换（is → is any of、include → include all of 等）；值个数变化时操作符等价归一（isAnyOf 单值 → is 等）。
- 多值字段 none 哨兵与真实值**互斥**（勾 No labels 即取消其它勾选）；单值字段可混选（No lead + 真人 = 未指派 OR）。
- 值行**分两区**（Linear 界面实测定稿）：checkbox 勾选区点击 = 本会话累积勾选（多选自动**合并为一个 chip**，菜单**不关闭**，可继续勾该属性其它选项或切其它属性）；其余区（文字）点击 = 单值直接成**一条 chip** 并**关闭整个菜单**（不再有机会点第二个选项）。
- 多选子面板贴近视口右缘时 Radix 会把飞出清单 popper 翻到 side=left，触发 onItemLeave 抢焦点误关 Sub——用**悬挂守卫**（指针仍在飞出清单内时忽略 focus-outside）阻断误关，指针移开其它字段行仍照常互斥关闭。
- filter / display / panel 收缩三按钮统一圆形形态。projects_page / tasks_page 的 Filter 为纯添加入口，**不亮蓝点**；两列表页 Display 在已有 View 浏览/编辑时比较保存 display，预设 tab 比较对应面的默认值；新建全程不亮蓝点、不展示 Reset（§4.4.1）。project_issues 尚未接 View：Filter 保留有条件即亮点的旧行为，Display 仍比较默认态。

### 2.3 空伪值契约

可空单值字段（assignee / lead / project）与多值 labels 族字段（labels）的值选择器提供空伪值选项（No assignee 等），wire 上编码为哨兵值 `none`；日期字段 startDate 亦提供 No start date：

- 单值可空：`none` ↔ NULL 双向映射；`isNot [x...]` 时 NULL 行按"伪值 ∉ 集合"判定 → **包含 NULL 行**（"assignee 不是 Lee"包含未指派任务，与 Linear 直觉一致）。单值字段 none 与真实值可混选。
- 多值：`none` 选中 = 空集合行；`inclAll [none]` = 无标签的行；`exclAny [none]` = 至少有一个标签的行（members 不支持 none）。**none 与真实值互斥**（勾 No labels 即取消其它勾选，Linear 实测）。
- members 字段不提供 none 选项（Linear 实测真值表）。
- priority 的 No priority 是真实值 0，不走哨兵。
- 日期空值条件走 `is`/`isNot` + `none`（No start date / No due date）；before/after 不参与空值判定。

### 2.4 日期相对条件

条件 = {字段, before|after, 阶梯码}（空值条件 = {字段, is|isNot, none}；逾期谓词 = {dueDate, is|isNot, overdue}，阶梯清单置顶行，chip 读作 "Due date is Overdue"；is = 非空且早于今天，今天到期不算逾期）。阶梯**按字段分方向**（Linear 实测真值表）：createdAt / updatedAt = ago 七档 `1d / 3d / 1w / 1mo / 3mo / 6mo / 1y`；startDate = from now 七档（同码未来偏移）+ No start date；targetDate = from now 仅三档 `3mo / 6mo / 1y`；dueDate = from now 仅五档 `1d / 3d / 1w / 1mo / 3mo`（Linear 实测无 6mo/1y）+ No due date + Overdue（Custom date or timeframe 后置 P3）。cutoff 由 **Go 层计算**（可测试）：timestamptz 列（createdAt/updatedAt）cutoff = now()±offset 比时刻；date 列（dueDate/startDate/targetDate）cutoff = today±offset 比日历日（civil.Date 算术；ago 取 −、from now 取 +）。`before` = 早于 cutoff、`after` = 晚于 cutoff。添加默认操作符：ago 档 = after（"晚于 N 前" = 近 N 内）、from now 档 = before（"早于 N 后" = 未来 N 内），chip 可切。

### 2.5 URL 编码与后端求值契约

- URL：重复查询参数 `f=<field>.<op>.<v1,v2>`，如 `f=status.isAnyOf.todo,in_progress&f=labels.inclAll.l1,l2&f=dueDate.after.3d&f=assignee.is.none&f=startDate.is.none`；解码白名单校验，非法条目静默丢弃（回退无该条件）。
- **求值层：Go 层条件列表引擎（internal/filter 包），2026-09 修订原"下沉 sqlc 数组参数"方案**。修订理由：条件列表模型条数动态（同字段可重复），sqlc 固定形状查询无法承载；多值字段重复 include 条件的 AND 无法折叠为单个数组参数（incl A ∧ incl B ≠ incl A∪B）；不分页前提下全量行集本就取回内存，labels/members 联结数据可在求值前批量取齐，与既有"动态排序放 Go 层"约定（api.md §2.2）同构，NULL/伪值语义单点可测试。
- 引擎契约：`filter.Parse`（f= 数组 + 实体字段白名单 Spec，非法条目静默丢弃）→ `filter.Apply`（行集 + 条件列表 + 实体字段值提取器，条件间 AND）。SQL 只保留基础谓词（workspace + 软删）与基底序；`ListTasksByWorkspace` 的 statuses 数组参数退役（handler 恒传非 nil 空切片，随后续查询清理删除）。
- 求值联结数据：labels 走 `ListLabelsByTaskIds` / `ListLabelsByProjectIds`；项目 members 由 `ListMembersByProjectIds` 批量组装进 ProjectRow.members，过滤提取器直接读取。旧 `ListProjectMemberIdsByProjectIds` 已退役，不再按 member 条件另查 ID 集合。
- 遗留参数：`filter=`（tasks）**已退役**（2026-09 A2 前端 tab 迁移完成，后端删除 `legacyStatusConds` 与 handler 分支；tab 作用域由页面侧合成进 f=，§1.4）；~~`sort=`/`order=`（projects）保留至 display options 切片前端化 ordering 时退役~~ **已退役**（2026-09 B 切片 ordering 前端化完成，后端删 `sort`/`order` 参数与 `sortProjects`，`TODO(P2-B)`；api.md §2.2 / §7 已回写）。
- React Query 键含实际请求的 `f` 参数 → 过滤切换按对应键取数（命中缓存可复用）；display 切换不进键、不发请求。

### 2.6 树形视图节点展示规则（2026-09-14 修订④成文定稿，用户 Linear 实测定稿）

**模式判定**（display 双开关，§3.4）：Show sub-issues 关 = 仅一级行；开 + Nested 关 = 平铺；开 + Nested 开 = 树形。本节主规则仅适用于**树形模式**；平铺模式见下「其它口径」。

**概念定义**：

- **基础行集**：后端取回的全部行（含已完成任务——链条/孤儿判定需要它们在场）。
- **展示行集**：基础行集经 Completed tasks 档与 Show sub-issues 档过滤后的行（flat 行 / 组头计数 / 树锚点同源于此）。
- **锚点**：展示行集中自身值命中当前组路径（一级组值 + 二级组值）的行；Completed=none 时已完成任务**不作锚点**。
- **渲染集（kept）**：组内实际渲染的树节点集合 = **锚点祖先链 ∪ 锚点完整子树**。

**主规则（规则④）**：

- **规则A（祖先链）**：锚点的全部祖先进入渲染集——非锚点祖先为**链条节点**，渲染并置灰。
- **规则B（完整子树）**：锚点子树内任意深度的后代，即使非锚点也进入渲染集并置灰（Linear 实测 sub2-2-1 / task8-1 例）——**子树展开权仅属锚点**。
- **侧分支剪枝**：链条节点的子树中不含锚点的分支（∉ 任何锚点子树）整体剪枝不渲染（Linear 实测 sub2 / task3 / gRPC 例）。

**Completed tasks = none 叠加层**（本产品档位，叠加在规则④上）：

- 已完成任务不作锚点，仅经规则A 以链条节点身份进入渲染集（置灰；task1 例）。
- 锚点子树内的已完成叶子：自身不入渲染集。
- 锚点子树内的已完成中间节点：自身不入渲染集，但**不阻断向下展开**（其下后代仍可经规则A/B 进入；task4 例）。链条上溯遇此情形须补全中间节点（实现层以独立 chained 集合判终止，不得以 kept 成员身份判，否则内层锚点先经规则B 入集时会跳过链条补全导致断链）。

**节点命运速查表**（组内任一节点 N）：

| # | N 的形态 | 命运 |
|---|----------|------|
| 1 | N 是锚点 | 渲染，正常亮度 |
| 2 | N 非锚点，但子树中含锚点（链条节点） | 渲染，置灰 |
| 3 | N 非锚点，是某锚点的任意深度后代（规则B） | 渲染，置灰；若 Completed=none 且 N 已完成 → 自身不渲染（不阻断其下后代入集） |
| 4 | N 非锚点，子树无锚点，且不属于任何锚点子树（侧分支） | 整体剪枝 |
| 5 | N 是孤儿（父不在基础行集） | 提为树根渲染，置灰 |

**其它口径**：

- 不分组（No grouping）树形同走渲染集：锚点 = 展示行集本身（Completed=all 不剪枝；=none 剪纯已完成子树）。
- **平铺模式不插父行**（用户定案）：仅渲染展示行集中自身命中的行，有父的行标题后带 “› 父标题” 面包屑（父被过滤/隐藏时孤儿同样带面包屑，延续 P0 行为）。
- Show sub-issues 关：仅一级行；父不在结果集的孤儿视为一级行渲染（避免行凭空消失）。
- 组头计数 = 锚点行数（flat/tree 同口径），不随剪枝/链条变化。
- 子树进度徽标 x/y = 真实子树口径（done 数 / 总数），不受剪枝影响。
- 置灰实现为 opacity-60；三条件并联：孤儿 / Completed=none 下的已完成链条节点 / 组路径值未命中。

**修订史**：C 切片初版（命中即整棵子树展示）→ ② 锚点最小生成林 → ③ 生成林 ∪ 锚点直接子节点 → **④ 锚点祖先链 ∪ 完整子树（现行）**；③ ⊂ ④，分叉点在「锚点深度 ≥2 的非锚点后代」（③ 剪、④ 留置灰）。实现单源：[task-display-state.ts](../../myLinearFrontEnd/src/lib/task-display-state.ts) 的 `taskSpanKeptSet` / `buildTaskGroupsTree`。

- 浏览态显示顶部 Filter/Display；新建/编辑态仅显示 panel 内两入口，Filter/Display 浮层互斥，模式切换时关闭浮层。New project / New task 与 tab 行 "+" 保留；写入或 View 数据未就绪时 "+" 禁用。

**Tasks 预设与作用域**

- Active / Backlog / All 保留，缺省/非法 `tab` 回 All；`view` 存在时优先按保存 View 解析，选 View 清 URL 的 `tab`，选预设清 `view` 并恢复该预设临时层。
- 预设浏览请求 = 隐式 status 基底 AND 临时 filters；临时条 Reset 只清临时条件，不清预设作用域。自定义 View 不叠加来源预设 status。
- 普通 "+" 不继承预设 status 或浏览 filters；新建/编辑预览仅用 draft。临时条 Create new view 携全部生效条件，因此从 Active/Backlog 另存会包含其 status 基底。
- Completed tasks 仅在 Active/Backlog 浏览态隐藏；All、自定义 View、新建/编辑均可配置，任务树/平铺仍由 Display 的子任务双开关决定。

**新建与已有 View 的生命周期**

| 操作 | 新建 View | 已有 View |
|---|---|---|
| 进入 | 普通 "+" 的名称/描述/filters 空，Display 深拷贝点击前生效值；临时条 Create new view 带全部生效 filters/display | Edit 优先恢复完整暂存草稿；无草稿才深拷贝保存元数据和 config，不使用浏览临时层初始化 |
| 切其他 tab / 历史导航切 tab | 关闭并丢弃新建草稿 | 关闭 panel、暂存完整草稿；点击 tab 仅浏览，再点 Edit 才恢复草稿 |
| 点击 "+" | 替换未保存新草稿，仍继承点击前 Display | 暂存原编辑草稿，打开新建 panel 并继承当前编辑 Display；取消新建不删除原编辑草稿 |
| Cancel | 丢弃新建草稿，恢复来源 tab 浏览 | 丢弃当前 View 的编辑草稿，恢复其浏览临时层；下次 Edit 从保存值开始，不影响其他 View 草稿 |
| Save 成功 | 激活新 View，新 View 临时 filters 空，来源 tab 浏览状态保留 | 写入元数据和 config，清除该 View 暂存草稿；退出编辑后 Display 使用新保存值，恢复本次提交时的浏览临时 filters |
| Save 失败 | 保留当前新建草稿供重试；之后切 tab 仍丢弃 | 不清编辑草稿；即使切 tab，再次 Edit 仍可恢复 |

- 保存请求未完成时允许切 tab；成功只清目标 View 草稿并更新其浏览缓存，不把用户拉回已离开的编辑会话。
- 浏览 **Save to this view** 将全部生效 filters/display 写入 config，成功后清空已吸收的临时 filters，清除该 View 旧编辑草稿；失败不清草稿。仅 Display 修改也可保存。同页吸收交接已处理，卸载异常仍见 §6 V3。
- 删除成功清除目标 View 的浏览与编辑缓存；删除当前 View 回预设 tab（Projects = All projects，Tasks = All），恢复该预设原临时缓存；删除其他 View 不切走。

**蓝点与 Reset**

| 状态/入口 | 蓝点或偏离判断 | Reset 的范围 |
|---|---|---|
| Filter 按钮 | 始终不亮蓝点（projects_page / tasks_page） | 无 Display Reset 语义 |
| 新建 panel 的 Display | **整个新建期间不亮**，包括继承非默认值及继续修改 | **不展示 Display Reset**；新建也无整体 Reset |
| 预设 tab 浏览 Display | 当前 Display 与本 surface 默认不等价时亮 | 仅还原默认 Display |
| 已有 View 浏览/编辑 Display | 当前正在展示的 Display 与该 View 保存 Display 不等价时亮；改回保存值即熄灭 | 仅还原保存 Display，不改 filters、名称或描述；编辑态仍留在 panel |
| 已有 View 编辑 panel 整体 Reset | 不依赖 Display 是否变化 | 将名称、描述、filters、display 全部还原保存值，并更新暂存草稿；不保存、不退出编辑、不改浏览临时层 |
| 浏览临时条 Reset | 有临时 filters 或 Display 偏离时出现临时条 | 清临时 filters，Display 恢复保存值/预设默认；不清隐藏编辑草稿 |

View tab 的偏离点与 Display 按钮蓝点不是同一指示：tab 比较其**浏览临时 filters 是否非空或浏览 Display 是否偏离保存值**，不因隐藏编辑草稿、名称或描述改动亮点。新建临时 tab 不显示偏离点。

| 后续操作 | 展示分组 | Display 蓝点 |

| 切去别处再点原 tab（浏览） | Lead | 亮 |
| 再次 Edit | Priority | 亮 |

| Cancel 回浏览 | Lead | 亮 |
| Cancel 后再次 Edit | Status；无旧草稿 | 灭 |
