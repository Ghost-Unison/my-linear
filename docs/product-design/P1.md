## 1. 相对 P0 的范围变更（2026-09 决策）

1. **内置固定视图取消，并入 P2**：内置视图本质是"config 写死、不落库"的 saved_view，与 P2 自定义视图同构；其设想载体——列表页 filter 按钮与 display options 按钮（对齐 Linear）——本身就是 P2 工作量，先做固定版半成品没有价值。P2 范围因此明确为三件套：saved_view CRUD、filter 按钮、display options 按钮。
2. **"按标签筛选与分组"随 filter 按钮后置 P2**：它的载体正是筛选条件与 Grouping 下拉。
3. **本阶段无新增路由**：P0 §4 中"P1 增加 /w/:wid/views 路由"的备注作废；Sidebar 不加 Views 入口。
4. **行完备原则（P2 兼容）**：列表/详情响应携带展示选项可能用到的全部字段，因为 P2 的展示选项（分组/排序/展示属性）是前端对已取回平铺行集的内存操作，切换不发请求（见 api.md §2.9）。由此修订：**ProjectRow 也返回 labels**（修订早前“项目列表不返回 labels”的决定）——数据返回但 P1 项目列表不渲染，展示留给 P2 display options。
5. **颜色字段契约统一（必填 + hex）**：label.color 与 member.avatarColor 均为前端必传 + `IsHexColor` 校验（修订 P0 的 avatarColor 可选约定；前端调色板默认预选色，不存在无色场景）；PATCH 显式 `null` → 400，不允许置空。
6. **打标 PUT 的包归属**：`PUT .../tasks/:id/labels` / `PUT .../projects/:id/labels` 分别放在 task / project 包（需复用包内的 `buildTaskDetail` / `buildProjectDetail` 装配响应，也因此这两个装配函数保持包内私有不导出）；label 包只承载 CRUD 与共享校验（`CheckLabelIDsLegal`：HTTP 适配层 + 错误码映射；`ValidateAndDedupeLabelIDs`：纯校验核心）。依赖方向 task/project → label，反向即循环依赖（读路径的行组装在 task/project 包，需引用 label 的类型与查询）。

## 2. Label 管理区（workspace Home 标签 tab）

**位置**：复用 P0 预留的 `?tab=label` tab（当前为 coming soon 占位），以 LabelsSection 替换占位，页面结构零改动。

- **分区**：tab 内两个 section：Task labels / Project labels（对应 scope 枚举），各自独立表格。
- **表格列**：色块（圆点）、name、操作（编辑、删除）；**无使用计数列**（裁剪）。
- **入口**：tab 激活时页头 action 区 "+ New label" 按钮（与 members tab 的 Add a member 同布局）。
- **创建/编辑弹窗**：name（必填，trim 后非空；同 scope 重名 → 409）、color（必填，**预设调色板点选**，约 12 个 hex 色板，不做自由 hex 输入）。
- **删除**：确认弹窗，说明"任务/项目上的该标签会同时移除，但任务/项目本体不受影响"（联结行 CASCADE，见 DATABASE_DESIGN §5）。
- **排序**：created_at ASC（后端固定）。
- Linear 式就地创建（选择器里输入新名字边选边建）为 P3。

## 3. 打标交互与标签展示

**统一原则**：打标入口只允许**勾选/移除已定义标签**（scope 必须匹配）；多选 popover 形态（复选列表），每次增删变更调用 PUT 打标接口（全量替换语义）。

| 位置 | 交互 |
|------|------|
| 任务新建弹窗 | labels 多选（scope=task），提交时传 `labelIds`，后端同事务写入 |
| 任务详情属性面板 | Labels 行 → popover 复选列表 |
| 任务列表行 | label chip 簇：色点 + name，位于行右信息区（assignee 之前）；子任务行（subtree）同样渲染 |
| 项目新建弹窗 | labels 多选（scope=project），提交时传 `labelIds` |
| 项目详情属性面板 | Labels 行 → popover 复选列表 |
| 项目列表 | **不渲染**标签列（行数据带 labels，展示留给 P2 display options） |

- chip 样式遵循 DESIGN-linear.app.md：圆角底 + 标签色点 + name（对齐 Linear issue 行标签 chip）。
- 无标签时属性面板行显示占位文案（与其他空属性一致）；列表行不渲染 chip 簇。

## 4. 后端接口要点

接口级契约见 [../api.md](../api.md)：新增接口见 §9；既有接口变更已回写 §4 对象模型与 §7 / §8 各查询条目。

**新增接口**：

| 接口 | 说明 |
|------|------|
| GET /workspaces/:wid/labels | scope 可选筛选参数，返回 Label[] |
| POST /workspaces/:wid/labels | 创建（name / color / scope） |
| PATCH /workspaces/:wid/labels/:labelId | 改名 / 改色 |
| DELETE /workspaces/:wid/labels/:labelId | 硬删除，联结行 CASCADE |
| PUT /workspaces/:wid/tasks/:taskId/labels | 任务打标，全量替换 |
| PUT /workspaces/:wid/projects/:projectId/labels | 项目打标，全量替换 |

**变更的既有接口**（URL 与方法不变，仅请求/响应形状扩展）：

| 接口 | 变更 |
|------|------|
| GET /workspaces/:wid/projects | ProjectRow 新增 `labels: LabelRef[]`（行完备原则；P1 列表不渲染） |
| GET /workspaces/:wid/projects/:projectId | ProjectDetail 继承 ProjectRow，带 labels |
| GET /workspaces/:wid/tasks | TaskRow 新增 `labels: LabelRef[]`，列表行 chip 渲染 |
| GET /workspaces/:wid/tasks/:taskId | TaskDetail 继承 TaskRow，带 labels |
| GET /workspaces/:wid/tasks/:taskId/subtree | TaskNode 新增 labels，子任务行与列表行同渲染 |
| POST /workspaces/:wid/tasks | 请求新增可选 `labelIds`，同事务写入 |
| POST /workspaces/:wid/projects | 请求新增可选 `labelIds`，同事务写入 |

**不变的接口**：workspace / member 全部接口、PATCH / DELETE task 与 project 的请求/响应形状均不变（PATCH 不含 label 字段，见下）。

实现要点：

- **规则 R6**：打标（含创建时 labelIds）校验 label 同 workspace 且 scope 匹配目标类型，违反 → 400。
- **响应 labels 组装**：行集查出后按 id 集合批量 `ListLabelsByTaskIds` / `ListLabelsByProjectIds`，handler 内存分组挂到各行（避免 N+1）；空标签返回 `[]`。
- 打标 PUT 实现为同事务 `DeleteXxxLabels` + `AddXxxLabels`（全量替换语义与项目 memberIds 一致）。
- PATCH task/project **不含** label 字段（标签统一走 PUT 子资源，避免两套替换语义入口）。

## 5. 模块 → 后端资源映射

| 前端模块 | 涉及资源 | 主要操作 |
|----------|----------|----------|
| Label 管理区 | label | CRUD（硬删除） |
